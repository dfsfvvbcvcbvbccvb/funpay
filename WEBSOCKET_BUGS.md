# Почему не работают WebSocket'ы (чат в LotInfo)

Разобрался, в чём дело. Проблема не в конфигурации (порт 8080 поднимается, синтаксис `app.js` в порядке), а в логике на бэкенде и фронтенде. Ниже — конкретные места.

## Backend: `backend/app.js`

### 1. `activeClients` создаётся заново на каждое подключение (строка 17)

```js
server.on('connection', async (ws) => {
    let currentUserId = null
    let activeClients = new Map()   // <-- вот тут
    ws.on('message', async (message) => {
        ...
        activeClients.set(Number(messageString.senderId), ws)
        ...
```

`activeClients` объявлена *внутри* колбэка `connection`, то есть у каждого нового WS-подключения — своя собственная пустая карта. Если пользователь A и пользователь B открывают чат — это два разных подключения, соответственно два разных `activeClients`, которые никогда не пересекаются. Карта в текущем виде вообще не выполняет роль общего реестра клиентов.

**Нужно:** объявить `activeClients` на уровне модуля (вне `server.on('connection', ...)`), чтобы она была общей для всех подключений.

### 2. Получатель ищется не по тому ID (строка 33)

```js
let receiverWs = activeClients.get(Number(messageString.senderId))
receiverWs.send(JSON.stringify(response))
```

Ищет по `messageString.senderId`, хотя отправлять новое сообщение нужно **получателю** (`receiverId`). Даже после фикса пункта 1 это будет просто отправлять ответ обратно тому, кто написал, а не собеседнику — то есть push второму участнику чата так и не долетит.

### 3. Нет проверки на `undefined` (строки 33-34)

Если в `activeClients` нет записи под нужным ID (получатель ещё не открывал сокет / не в сети), `receiverWs` будет `undefined`, и `receiverWs.send(...)` кинет необработанное исключение внутри `async` колбэка `ws.on('message', ...)`. Клиент в этот момент просто не получает вообще никакого ответа — выглядит как зависший сокет, а по факту сервер упал с exception на этом сообщении.

### Побочное
- `parsed` (строка 19, `let parsed = JSON.parse(message)`) нигде не используется — мёртвый код, признак незаконченной правки.

## Frontend: `frontend/src/components/LotInfo.jsx`

### 4. `socket` — обычная переменная компонента, а не `useRef`/`useState` (строка 26)

```js
let socket = null
const ws = useRef(null);
```

`socket` объявлена как обычный `let` в теле функционального компонента. При каждом ре-рендере React пересоздаёт тело компонента — значит `socket` каждый раз снова `null`.

Из-за этого проверки:
```js
// getMessages, строка 82
if (socket === null) {
    socket = new WebSocket('ws://localhost:8080')
}
```
```js
// handleSendMessage, строка 252
if (socket === null) {
    ws.current = new WebSocket('ws://localhost:8080');
} else {
    ws.current = socket
}
```
почти всегда открывают **новое** соединение, вместо того чтобы переиспользовать уже живое из `ws.current`. `ws.current` для этого и заведён (пережил бы ре-рендеры), но код его игнорирует и сверяется с локальной `socket`, которая никогда не "запоминается" между рендерами.

Итог — на каждый вызов `getMessages`/`handleSendMessage` плодится новый сокет, обработчики `onopen`/`onmessage` перевешиваются на новый инстанс, а старые соединения просто повисают.

### Побочное
- Отладочные `alert('sfdc')`, `alert('123')`, `alert('321')` (строки 86, 98, 101) — похоже, забытые при отладке, стоит убрать.

## Вывод

Даже если поправить только бэкенд (пункты 1-3), фронтенд всё равно будет плодить лишние соединения из-за пункта 4 и не сможет нормально держать одно стабильное соединение. Нужно чинить оба конца:

- Backend: общий `activeClients` на уровне модуля + поиск по `receiverId` + guard на `undefined`.
- Frontend: держать сокет в `useRef` (или `useState`) и переиспользовать его между рендерами вместо пересоздания.
